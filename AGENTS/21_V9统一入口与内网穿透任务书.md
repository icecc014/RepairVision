## 1. 问题诊断：为什么打开 `http://localhost:8080/` 不行

### 1.1 实测（2026-09-20，容器运行中）

| 请求 | 结果 |
| :--- | :--- |
| `GET http://localhost:8080/` | **404** |
| `GET http://localhost:8080/login` | **404** |
| `GET http://localhost:8080/admin/` | 200 |
| `GET http://localhost:8080/m/` | 200 |
| `GET http://localhost:8081/` | **404** |

### 1.2 根因

1. **`nginx.conf` 从来没有定义 `location /`**。当时只定义了 `/admin/`、`/m/`、`/favicon.ico`、三个角色短入口（`/dorm`、`/worker`、`/report`）以及 `/api/`、`/ping/`、`/ws/`。
   请求 `/` 匹配不到任何 location，nginx 只能使用编译期默认 root（镜像内的 `/etc/nginx/html`，该目录并不存在）→ 404。
2. **根目录本身没有首页文件**。`deploy/docker/web.Dockerfile` 只把构建产物拷进 `/usr/share/nginx/html/admin` 与 `/usr/share/nginx/html/m`，`/usr/share/nginx/html` 下没有任何 `index.html`。
3. `8081` 与 `8080` 共用同一个 server 块，因此行为完全一致。

### 1.3 结论

> **不是端口没起来，也不是服务没部署**——8080 上的 `/admin/`、`/m/` 一直是 200。
> 真正缺的是「**根路径没有被定义**」，也就是**没有统一登录页**。这正是 V9 要补的第一件事。

（旁证：`docker ps` 显示 8 个容器全部 Up，`repairvision-web-1` 映射 `0.0.0.0:8080->80` 与 `0.0.0.0:8081->80`。）

| 路径 | 指向 | 使用者 | 需要登录 |
| :--- | :--- | :--- | :---: |
| `/`、`/login` | 统一登录页（`frontend/login`） | 所有人 | ❌ |
| `/admin/` | PC 管理端 SPA | 超级管理员（role=1） | ✅ |

## 4. 设计

### 4.1 统一登录页（`frontend/login/`）

| 项 | 设计 |
| :--- | :--- |
| 形态 | **纯静态 HTML + CSS + 原生 JS**：无构建步骤、**零新增依赖**（不使用 Element Plus / Vant，符合 `01_项目规约.md` 依赖白名单约束） |
| 文件 | `index.html` / `styles.css` / `app.js` |
| 视觉 | 复用 V4 设计令牌：柔和渐变背景 + 柔光斑、玻璃拟态卡片、18px 圆角、`cubic-bezier(0.22,1,0.36,1)` 动效、渐变主按钮 |
| 响应式 | ≥860px 分栏（左品牌 / 右表单）居中；<860px 竖屏单列，仅留紧凑品牌头，控件放大到 48px 触控高度 |
| 接口 | `POST /api/login`（与三端完全共用一个接口） |
| 演示便利 | 演示账号胶囊（admin / dorm1 / water1 / elec1）一键填充 |
| 已登录处理 | 显示「继续进入 / 切换账号（退出登录）」，避免「退出即被自动跳回」的死循环 |
| 公共入口 | 底部「我要报修（学生 / 教师，无需登录）」→ `/report` |

### 4.2 登录态键位（关键设计）

| 键 | 存储 | 写入者 | 读取者 |
| :--- | :--- | :--- | :--- |
| `rv_token` / `rv_user` / `rv_role` | localStorage | 统一登录页 | V9 共享登录态（预留） |
| `rv_admin_auth` / `rv_admin_token` | localStorage | 统一登录页、PC 管理端自身登录 | PC 管理端 axios 与路由守卫 |
| `rv_token` / `rv_user` | sessionStorage | 统一登录页、移动端自身登录 | 移动端（同标签页） |

**取舍说明**：项目原有设计是「移动端登录态放 sessionStorage，不同角色各开标签页互不影响」。V9 **保留**该隔离语义——移动端仍优先读 sessionStorage（本标签页身份），**仅在 sessionStorage 为空时**回退 localStorage 共享登录态。因此：

- 从统一登录页登录 → 立刻落到对应端，无需二次登录；
- 想同时开两个角色标签页时，后开的标签页因角色校验不通过会被送回登录页（而不是串号），与既有验收口径一致。

### 4.3 Nginx

```nginx
    # 统一登录页（V9）：根路径与 /login 都进入统一登录页
    location = / {
        return 302 /login/;
    }

    location = /login {
        return 302 /login/;
    }

    location /login/ {
        alias /usr/share/nginx/html/login/;
        index  index.html;
        try_files $uri $uri/ /login/index.html;
    }
```

说明：沿用项目既有写法（`alias` + `try_files` 回落到自身 `index.html`，与 `/admin/`、`/m/` 一致）；登录页资源使用绝对路径 `/login/*`，避免 `/login`（无尾斜杠）下相对路径解析到根目录。

### 4.4 前端守卫

| 端 | 改动 |
| :--- | :--- |
| mobile-web | `src/api/http.ts`、`src/stores/auth.ts`：token / user 读取改为 sessionStorage 优先 + localStorage 兜底 |
| pc-admin | `src/router/index.ts`：持有 `role != 1` 登录态时直接 `logout()` 并跳回 `/login/`，防止工人 / 宿管进入管理端 |

两个前端仍各自独立构建（不改 build 配置、不新增依赖）。

### 4.5 镜像与启动

- `deploy/docker/web.Dockerfile`：新增 `COPY frontend/login /usr/share/nginx/html/login`（静态目录，无需 node 构建阶段）。
- `scripts/up.ps1`：启动后打印统一入口地址。

## 5. 内网穿透部署设计

### 5.1 方案对比与选型

| 工具 | 类型 | 优势 | 免费版限制 | 本项目适用性 |
| :--- | :--- | :--- | :--- | :--- |
| **cpolar** | 商业 | 国内节点、自带 HTTPS、Web 管理界面 | 域名 24h 重置、带宽/连接数受限 | ✅ **演示期首选** |
| 花生壳 | 商业 | 国内老牌、可固定壳域名、支持 HTTPS | 需实名、免费带宽流量受限 | 微信调试备选 |
| ngrok | 商业 | 开箱即用 | 域名随机、海外节点延迟大 | 临时调试 |
| **frp** | 开源自建 | 免费、高性能、地址固定 | 需自备公网服务器 | ✅ **长期/固定地址** |

**结论**：毕设演示用 **cpolar**（成本 0、5 分钟可用、微信可打开）；若后续要固定地址长期在线，再上 **frp**。

### 5.2 穿透后架构

```text
同学 / 导师 / 手机 / 微信
        │  https://xxxx.cpolar.cn
        ▼
   cpolar 公网节点（自动签发 HTTPS）
        │  加密隧道
        ▼
   本机 127.0.0.1:8080        ← 注意：填宿主映射端口 8080，不是容器内的 80
        ▼
   repairvision-web-1（Nginx:80）
        ├── 静态：/login/  /admin/  /m/
        ├── /api  → order-api:8888
        └── /ws   → order-api:8890（WebSocket）
```

### 5.3 cpolar 实施步骤（Windows）

1. 官网注册并安装客户端；
2. 浏览器打开 `http://localhost:9200` 登录本地管理界面；
3. 「隧道管理 → 创建隧道」：名称 `repairvision`、协议 `HTTP`、本地地址 `127.0.0.1`、**本地端口 `8080`**；
4. 取得公网地址（形如 `https://xxxx.cpolar.cn`）；
5. 按下列清单验收。

| 检查 | 期望结果 |
| :--- | :--- |
| `https://xxx/` | 统一登录页（302 → `/login/`） |
| `https://xxx/admin/` | 200 |
| `https://xxx/report` | 公共报修页可提交、可查询 |
| 登录 `admin` | 落到 `/admin/` |
| 登录 `water1` | 落到 `/m/worker` |
| 登录 `dorm1` | 落到 `/m/dorm` |
| 页面实时刷新 | `/ws/orders` 握手 101 |

**关键坑**：本地端口填 **8080**（宿主端口）。V9 起统一入口就在 8080，8081 仅作兼容保留，不必穿透。

### 5.4 WebSocket 穿透要点

Nginx 已为 `/ws/` 配置 `Upgrade` / `Connection` 头并转发到 `order-api:8890`，穿透工具需支持 WebSocket（cpolar HTTP 隧道、ngrok 免费版均支持）。若公网下实时推送失效，排查顺序：隧道是否支持 ws → 浏览器控制台 `/ws/orders` 是否 101 → `order-api` 容器日志。

### 5.5 安全与运维

| 项 | 要求 |
| :--- | :--- |
| 只暴露 web | 只穿透 8080；**绝不**把 MySQL(3306)、Redis(6379)、Kafka(9092)、Etcd(2379) 暴露或穿透 |
| 演示期开关 | 演示结束立即关闭隧道；`.env` 不入库（已 gitignore） |
| 地址变化 | 免费版地址会变；每次演示前确认地址并重新生成二维码（注意微信 DNS 缓存） |
| 带宽 / 并发 | 免费版有限，演示控制同时在线人数；答辩大屏建议直接用本机 8080 |
| HTTPS | 公共报修在微信内打开建议用 https（cpolar 默认提供） |
| 限流 | 公共报修已有图形验证码 + IP / 房间双维度限流，公网暴露下依然生效 |
| 数据 | 穿透只暴露 Web 层，数据库仍在本地 Docker 内网，不对外网开放 |

### 5.6 为什么「换地址不用改代码」

- 两端 axios 均为 `baseURL = '/api'`（相对路径）；
- 路由 base 分别为 `/admin/`、`/m/`；登录页资源用 `/login/*` 绝对路径；
- 因此无论地址是 `localhost`、局域网 IP 还是 `xxxx.cpolar.cn`，**都不需要改代码或重新构建**，只换访问地址。
