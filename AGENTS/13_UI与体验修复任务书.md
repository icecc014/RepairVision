## 1. 工单总览列表 UI 重叠 ✅（本次已改，待你目视确认）

- **现象**：工单列表观感差、元素相互重叠。
- **原因**：「状态」列固定 105px，却要放下"状态徽标 + 待管理员处置/外援处理标签 + 已锁定标签 + 待派原因"多行内容，标签宽度超出列宽压到相邻列；「操作」列 430px 要放 5 个按钮，容易折行。
- **方案**：状态列加宽到 **176px**；锁定/处置标签改为**行内左间距**（不再换行堆叠）；待派原因最大宽度 176px；操作列加宽到 **540px** 并加 `op-cell { white-space: nowrap }` 防止按钮折行。
- **涉及**：`frontend/pc-admin/src/views/HomeView.vue`
- **验收**：桌面宽度 ≥1440px 下，列表无重叠；1920px 下所有按钮一行显示。

## 2. 区域概览页面布局重排（工具 / 画布 / 属性同屏）✅（本次已改）

- **现象**：「图元属性」被挤到画布下方，需要滚动才能改属性。
- **原因**：页面 `.layout` 是三栏网格（工具 200px | 画布 1fr | 属性 240px），但 V5.4 新增的「路网与距离」面板被插到属性之前，导致第 4 个子元素换行到第二行。
- **方案**：把「路网与距离 + 图元属性」包进 `.side-col`（纵向堆叠、可独立滚动，max-height 80vh），第 3 栏扩到 **330px**，`.layout { align-items: start }`；工具 210px。这样**左侧工具、中间画布、右侧属性+距离**同屏可见。
- **涉及**：`frontend/pc-admin/src/views/CampusOverviewView.vue`
- **验收**：1440px 宽度下，三栏同屏；选中图元后可直接在右侧改名称/位置/尺寸，无需滚动页面。

## 3. H5（工人端）看不到区域概览，显示"管理员尚未绘制" ✅（已加固：可诊断 + 重试 + 空图元不再误报）

- **现象**：管理端已保存区域概览，但 H5 端仍显示"管理员尚未绘制"。
- **可能原因**（按概率）：① H5 组件解析 `layoutJson` 时 blocks 为空（字段名/结构不一致）；② 请求未带 token 或 401 被静默吞掉；③ 组件 `autoLoad` 未触发。
- **方案（下一步诊断）**：在工人端控制台执行
  `JSON.parse((await fetch('/api/campus-map',{headers:{Authorization:'Bearer '+sessionStorage.getItem('rv_token')}}).then(r=>r.json())).data.layoutJson).blocks.length`
  —— 若 > 0 则问题在前端解析，若为 0/报错则在后端返回。
- **涉及**：`frontend/mobile-web/src/components/CampusOverviewMap.vue`、`api/index.ts`
- **验收**：工人端展开「校园概览」能看到与管理端一致的图元与建筑名称。

## 4. 工人端楼栋示意图应固定尺寸 ✅（已改为固定最小可视范围 640×420）

- **现象**：只有 1 栋楼有维修任务时，Konva 画布把这一栋放大占满整个区域，观感差。
- **原因**：`MapView.vue` 的 `scaleBounds()` 按"当前有单楼栋的包围盒"自适应缩放。
- **方案**：改为**固定世界坐标范围**（用全部楼栋的包围盒为基准，或直接固定 0~1000×0~700 的世界坐标），缩放比固定；单栋有单时也保持与多栋一致的比例，楼栋在画布中的相对位置稳定。
- **涉及**：`frontend/mobile-web/src/views/MapView.vue`
- **验收**：1 栋/4 栋有单时，楼栋方块尺寸与位置比例一致，不再放大占满。

## 5. 工人端 2D/3D 只显示"派给自己的工单" ✅（已核对：2D/3D 均直接用 map.orders，即该工人的活动工单）

- **现象**：2D/3D 之前能看到楼栋内所有维修故障，需改为只显示派给自己的单。
- **现状**：后端 `/api/worker/map-data` 已改为**只返回该工人的活动工单**（P0-1 改造），2D/3D 组件读取的是 `map.orders`。
- **方案**：核对 `MapView.vue` → `BuildingFloorPlan.vue` / `Building3D.vue` 的传参，确保传入的是 `map.orders`（而非按楼栋重新拉取的全量工单）；若存在"按房间匹配"逻辑，需再按 `workerId` 过滤。
- **验收**：用两名工人分别登录，各自 2D/3D 只显示自己的工单数与房间。

## 7. 区域概览：长按拖动建筑（带碰撞回退）⏳

- **需求**：鼠标左键**按住约 300ms**进入拖动模式 → 移动过程中实时预览位置 → 松开时：
  - 若与其它图元**重叠** ⇒ **回退到拖动前的位置**（并提示"该位置与其它图元重叠，已还原"）；
  - 不重叠 ⇒ 提交新位置（记入撤销栈）。
- **方案**：
  - 在 `CampusOverviewView.vue` 的 `onBlockDown` 中加计时器：`pointerdown` 起 300ms 未抬起且未进入编辑模式 → `dragging = true`；
  - 拖动中按 `floor((clientX-rect.left)/cellW)` 计算目标格，实时更新 `dragGhost`（半透明预览）；
  - `pointerup` 时用现有 `campusAreaFree()`（排除自身）做碰撞检测：失败则回退 `dragStartSnapshot`，成功则 `pushHistory()` + 落位；
  - 拖动阈值（300ms / 3px）与"不改变尺寸"约束：拖动只改 `row/col`，不改 `rowSpan/colSpan`。
- **涉及**：`frontend/pc-admin/src/views/CampusOverviewView.vue`（含新增拖动状态与样式）
- **验收**：拖动建筑到与其它建筑重叠处松手 → 建筑弹回原位并提示；拖到空位 → 位置生效，Ctrl+Z 可撤销。

## 8. 建筑信息管理 2D 坐标 ↔ 区域概览位置对应 ⏳（需先定口径）

- **现状**：`map_db.buildings` 有 `pos_x / pos_y`（楼栋在校园平面中的坐标，管理员在「建筑信息管理」里维护）；区域概览的图元用**网格行列**定位，两者独立。
- **对应关系建议**（三选一，需你拍板）：
  1. **单向同步（推荐）**：以区域概览为准 —— 保存概览时，把每个"关联楼栋"图元的**中心格坐标**换算为 `pos_x/pos_y`（`pos_x = (col + colSpan/2) × 格边长`），写回建筑信息管理；建筑信息管理里的坐标改为**只读展示**（并标注"由区域概览自动同步"）。
  2. 双向绑定：任一侧修改都同步另一侧（需处理冲突，复杂度高）。
  3. 保持独立，仅在建筑信息管理里增加"在概览中的位置"只读列（最小改动，但两处数据可能不一致）。
- **价值**：`pos_x/pos_y` 是 V4 欧氏距离派单的基础；与概览一致后，欧氏距离与路网距离的对比实验才有一致的地理基准（实验一需要）。
- **验收**：在区域概览中移动/调整建筑后，建筑信息管理中的 2D 坐标列同步更新（方案 1）。
