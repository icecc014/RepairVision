## 1. 一句话口径（30 秒自我介绍）

> 这是**校园维修工单智能调度与 2D/3D 混合可视化系统**。宿管或学生发起报修，系统按**技能 40% + 路网距离 30% + 负载 30%** 自动派单给最合适的工人，工人现场维修并完工反馈，全过程在 PC 管理端、宿管端、工人端与统计看板上实时同步；差异化在于把校园总平面图栅格化成路网，让派单真正"懂空间"，并提供楼宇 2D/3D 可视化。

技术栈一句话：Go（go-zero）+ MySQL / Redis / Kafka + Vue3（Element Plus / Vant）+ Konva / Three.js，Docker Compose 八容器一键启动。

## 4. 答辩 Q&A（高频）

| # | 问题 | 口径要点 |
| :---: | :--- | :--- |
| 1 | 时间窗怎么算？ | 1/3/7/30 天 = **自然日（含今天）**，三端口径一致 |
| 2 | 并发上限？ | 默认上限 8，软上限 = 并发 + 2；**超限不拒派**，只施加动态负载惩罚 |
| 3 | 派单评分？ | 技能 40% + 路网距离 30% + 负载 30%，权重可配 |
| 4 | 候选工人怎么定？ | 在岗 ∧ 工种匹配 ∧ 启用 ∧ 未请假；在岗 = 今日白班 ∧ 时段内 ∧ 未请假 ∧ 启用 |
| 5 | 距离怎么算？ | 优先**路网最短路**（总平面图道路图元栅格化 + 建筑接最近路网节点 + Dijkstra 距离矩阵缓存）；无路网回退欧氏距离 |
| 6 | 保护线？ | 只看**待派单量**（人均倍数与绝对单量取大者）；等待时长用于预警与超时强制恢复 |
| 7 | 工单合并规则？ | 同楼栋 + 同房间 + 同类型、3 天内且主单未完成 → 并入主单，`order_duplicate_records` 留审计 |
| 8 | 公共报修怎么防刷？ | 图形验证码 + IP 每分钟 3 次 + 同房间 30 分钟 1 次 + 敏感词 |
| 9 | 为什么不用第三方地图？ | 校园场景规模小、需要"道路参与派单"，自绘 SVG + 栅格化能完全掌控数据源，也避免外部依赖与配额 |
| 10 | 3D 怎么实现？ | Three.js 楼体 + 楼层 2D 平面（Konva），楼宇数据来自 map-rpc |
| 11 | 微服务怎么拆的？ | order-api（工单/派单/排班/规则）、worker-rpc（人员/技能/管辖/排班）、map-rpc（楼宇/布局/故障标记），三库通过 RPC 交互 |
| 12 | 为什么禁止跨库？ | 三库各自单一职责，跨库数据一律走 RPC，避免耦合与一致性问题 |
| 13 | Kafka 做什么？ | 操作日志异步落库（topic `operation-logs`），KRaft 单节点，不依赖 ZooKeeper |
| 14 | 登录态怎么设计的？ | 统一登录页一次登录写三类键（共享 `rv_token` / `rv_user` / `rv_role` + 管理端自有键 + 移动端 sessionStorage），移动端"本标签页优先、共享兜底"，既免二次登录又避免多角色串号 |
| 15 | 数据规模？ | 28 栋楼（1~26 号 + 过渡 1/2 栋）、10 名工人（水 4 / 电 3 / 泥瓦 1 / 木 2）、28 个宿管账号、203 张测试工单（含已完成 183 张，按真实概率生成） |

**口径红线（不承诺）**：多租户、OAuth 第三方登录、域名备案、免费穿透域名的长期可用性、白名单外的第三方库。

## 6. 现场故障应对

| 现象 | 快速处置 |
| :--- | :--- |
| 公网地址打不开 | 立刻切回本机 `http://localhost:8080/`；穿透只影响手机/微信环节 |
| 页面白屏或卡顿 | 已预热过的标签页优先；否则切录屏 |
| WebSocket 不推送 | 检查浏览器控制台 `/ws/orders` 是否 101；公网下若是隧道不支持 ws，改用本机大屏演示 |
| 登录后跳错端 | 用"切换账号"回到统一登录页重新登录（不要手工清缓存，脚本与页面已处理失效落点） |
| 演示数据被改乱 | `scripts\demo-data.ps1` 重新生成演示数据（按需） |

## 8. 穿透隧道操作（cpolar，V9.3 已实测通过）

```powershell
# 启动隧道（必须指定国内区域；默认 us 会被账号策略拒绝，表现为一直 reconnecting）
& F:\icey\RepairVision\.tools\cpolar\cpolar.exe http -region=cn 8080 -log=stdout

# 查看隧道状态与公网地址（本地管理界面）
start http://127.0.0.1:4040
```

| 项 | 说明 |
| :--- | :--- |
| 公网地址 | 形如 `https://xxxx.r9.cpolar.cn`；**免费版每次启动都会变，演示前必须重新确认** |
| 一次实测 | `https://282d6104.r9.cpolar.cn`：`check-entry.ps1 -BaseUrl … -CheckWs` 15/15 通过；WS 带 token 握手 101 |
| 验收命令 | `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-entry.ps1 -BaseUrl https://xxxx.cpolar.cn -CheckWs` |
| 关闭 | 结束运行隧道的窗口/进程（任务管理器结束 `cpolar.exe`），或在管理界面停止隧道 |
| 只穿透 Web | 只映射宿主 `8080`；**绝不**穿透 MySQL / Redis / Kafka / Etcd |
| 排障 | `# Conn 0` + `Tunnel Status reconnecting` 多为区域/账号策略或隧道未建立，不是网络故障；先看 `http://127.0.0.1:4040` |
