## 1. 需求 → 设计

### 1.1 「我的画布」模板库 + 使用此模板（需求 1）

**数据模型**（新表，不动现有 `campus_layouts` 语义）：

```sql
create table if not exists order_db.campus_layout_templates (
  id bigint primary key auto_increment,
  name varchar(100) not null unique,
  grid_cols int not null default 100,
  grid_rows int not null default 80,
  layout_json longtext,
  source varchar(20) not null default 'manual',   -- manual / auto-backup
  created_by bigint default 0,
  created_at datetime default current_timestamp,
  updated_at datetime default current_timestamp on update current_timestamp
);
```

- `campus_layouts`（id=1, is_default=1）继续表示**当前生效地图**：宿管端/工人端 `/api/campus-map` 读它，接口零改动，其他端立刻可见。
- 模板是**快照**：编辑时随便存，不影响其他人；只有「使用此模板」才把模板内容复制进当前生效地图。

**接口**（全部 admin 权限，手写 handler + logic，按项目约定不重跑 goctl）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/campus-templates` | 模板列表（id/name/cols/rows/source/updatedAt），不含大 JSON |
| POST | `/api/admin/campus-templates` | 保存为新模板（同名 = 覆盖，带 `overwrite` 标记） |
| GET | `/api/admin/campus-templates/:id` | 读取单个模板内容（加载到编辑器） |
| PUT | `/api/admin/campus-templates/:id` | 重命名 |
| DELETE | `/api/admin/campus-templates/:id` | 删除 |
| POST | `/api/admin/campus-templates/:id/apply` | **使用此模板**：复制进当前生效地图 + 同步建筑坐标 + WS 广播 + 应用前自动备份 |

**安全网**：「使用此模板」前，先把当前生效地图另存为 `应用前备份 YYYY-MM-DD HH:mm`（`source='auto-backup'`），
只保留最近 5 条自动备份，避免"一个模板覆盖掉画了很久的图"。

### 1.2 只读视图 + 编辑模式（需求 2）

- **默认 = 查看模式**：整页只显示当前生效地图（只读），支持缩放/拖动；隐藏图元工具与属性面板。
- 点「编辑」进入编辑模式，弹选择：
  1. **新建空白画布**（沿用当前网格尺寸，或自定义行列）；
  2. **加载我的画布**（选择模板 → 载入编辑器，此时**尚未生效**，需点保存才影响其他人端）。
- 编辑模式工具条：`保存`（写回当前生效地图 → 其他端可见）、`保存到我的画布`（命名快照）、`放弃修改`、撤销/重做。

### 1.3 派单工种错配（需求 3）

**根因（已定位）**：建单路径 `createorderlogic.go` 有 `jobTypeAllowed` 过滤，但**兜底扫描 / 批量派单路径
`AdminBatchDispatchLogic` 完全没有工种过滤**——它只判断"是否同一楼栋"。今天 18:31 的一次兜底扫描把
电维修单派给了水工（`dispatch_records` 中 5 条错配全部来自这条路径）。

**修复**：批量派单在候选与成本矩阵两处都加 `jobTypeAllowed(worker.JobType, requiredJobTypeOf(category))`；
该楼栋没有匹配工种的工人时留在待派队列（`Remained`），并在日志里说明原因。另外补一条单测。

**历史错配数据**：7 条已完成/在途错配单可保留（不影响功能），需要回炉的话用脚本把在途单退回待派，等你确认再做。

### 1.4 图元自定义颜色（需求 4）

- `CampusBlock` 增加可选字段 `color?: string`（`parseCampus/serializeCampus` 原样透传，向后兼容）。
- 图元属性面板增加取色器：预设 12 色 + 自定义 RGB/HEX（`el-color-picker`）。
- `blockStyle` 优先使用 `color`（自定义色自动配深一点描边）；H5 端 SVG 同步填色。

### 1.5 建筑编辑不得覆盖布局（需求 5）

**根因**：`BuildingsView` 编辑弹窗只提交名称/编码等字段，`layoutJson` 缺失 →
`AdminBuildingUpdateLogic` 传空串 → `map` 服务 `update buildings set layout_json=''` → 布局被清空，
页面回退到"内置标准层"。

**修复**：

- `AdminBuildingUpdateLogic`：`layoutJson` 为空 → 复用建筑当前的 `layoutJson`（只有布局设计器能改布局）；
- 需要"清空自定义布局"时，前端显式传哨兵 `__DEFAULT__` → 后端写成空串（回退内置标准层）。

### 1.6 内置标准层 = 1 号楼自定义布局（需求 6）

- 你现在的 1 号楼自定义布局：`7 × 10` 格、28 图元（16 房 + 8 走廊 + 2 楼梯 + 2 公共区）。
- 用脚本 `scripts/gen-standard-floor.mjs` 从该 JSON 生成双端共享常量
  `frontend/{pc-admin,mobile-web}/src/utils/standardFloor.ts`；
- `layoutGrid.ts` 的 `defaultLayout()` 与 `resolveFloorPlan()` 回退分支改为使用该常量，
  新建建筑/一键生成标准层/清除自定义布局后，看到的都是你做的这张标准层。

## 4. V6.2 修订（按用户 2026-09-16 反馈）

### 4.1 保存流程改为两步（取消“一键保存并应用”）
- 编辑模式按钮：`保存到我的画布`（主按钮）；保存成功后画布上方出现提示条：
  “已保存到我的画布「X」。要让它成为其他端看到的地图，请退出编辑模式后在右上角点「使用此模板」。”
- 让宿管端 / 工人端看到新地图的唯一入口 = 查看模式的 `使用此模板`（会先自动备份当前地图）。
- 好处：编辑期间怎么改都不影响其他端，可以先把多套方案存成不同画布，再逐一“使用此模板”对比。

### 4.2 备份与恢复（新增）
- 新表 `order_db.sys_settings`（通用键值配置），键 `campus_backup_keep`（默认 5，范围 1~50）。
- 接口：
  - `GET /api/admin/campus-backups` → `{ list:[{id,name,cols,rows,blocks,buildings,bytes,createdAt}], keep }`
  - `POST /api/admin/campus-backups` → 立即备份当前生效地图
  - `POST /api/admin/campus-backups/:id/restore` → 恢复某一版（恢复前先自动备份当前地图，可再次回退）
  - `PUT /api/admin/campus-backups/keep` → 修改保留份数并立即裁剪
- 自动备份时机：`使用此模板` / `恢复某一版`；命名 `应用前备份 时间`、`备份 时间`；只保留最近 N 份。
- 前端：查看模式工具条 `备份与恢复` 打开面板（列表含 备份时间 / 格数与图元数与建筑数 / 名称 / 恢复此版本；顶部可“立即备份当前地图”与调整保留份数）。

### 4.3 本阶段实测
- 备份列表：keep=5，`应用前备份 2026-09-16 19:04:31` → 100×80 格、145 图元（建筑 28）。
- 立即备份 → 列表变 2 条；保留份数改 8 → 生效并裁剪；恢复接口调用成功。
- 浏览器实测：编辑模式按钮 = 生成示例布局 / 清空画布 / 放弃修改 / 应用画布尺寸 / 保存到我的画布（已无“保存并应用”）；保存后提示条文案正确。
