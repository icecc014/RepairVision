# 25_V9.8 密码修改与会话强制失效任务书

> 归属：**V9 阶梯**（2026-09-20 用户确认）
> 目标：管理员能在「人员账号 → 编辑」里直接设置新密码；改密成功后，**该账号在其它端的旧登录态立即失效**，必须用新密码重新登录。
> 相关：`21_V9统一入口与内网穿透任务书.md`、`24_V9.7管理端移动自适应任务书.md`

---

## 1. 背景与问题

- 原系统使用**无状态 JWT**：改密码不会让已签发的 token 失效，别人拿着旧 token 仍可继续访问。
- 前端原本只有列表里的「重置密码」按钮，编辑弹窗内没有设置密码的入口。
- 后端 `AdminUserResetPasswordRequest` **本来就带 `Password` 字段**，所以"指定新密码"无需改接口。

## 2. 方案选择

| 方案 | 做法 | 结论 |
| :--- | :--- | :--- |
| A1 | 每次请求经 RPC 查 DB 版本号 | 实时性最好，但每请求一次 RPC，开销最大 |
| **A2（采用）** | 版本号存 Redis，鉴权时比对；改密后递增 | 零额外 RPC、实时性足够（改密即生效） |
| A3 | 仅敏感接口实时校验 | 实现复杂、口径难解释 |
| B | Redis 记录会话白名单 | 需要登录写会话，改动面更大 |
| C | 仅前端清登录态 | 挡不住旧 token，不能宣称"强制下线" |

## 3. 实现（方案 A2）

| 环节 | 落点 | 说明 |
| :--- | :--- | :--- |
| 版本号存储 | Redis `pwdver:<uid>`（TTL 一年） | 复用 order-api 现有 `PubCache`，不新增依赖 |
| 版本号模块 | `services/order/internal/auth/version.go` | `UsePwdVersionStore / CurrentPwdVersion / BumpPwdVersion / pwdVersionOK` |
| 签发 | `logic/loginlogic.go` | 登录时读版本号写入 JWT claim `pwdver` |
| 鉴权 | `auth/roleguard.go` | 比对 token 版本与 Redis 版本，不一致 → 401「登录状态已失效，请重新登录」 |
| 改密 | `logic/adminuserresetpasswordlogic.go` | 成功后（defer 中判 `err == nil`）`BumpPwdVersion` |
| 注入 | `handler/routes.go` | 启动时 `auth.UsePwdVersionStore(serverCtx.PubCache)` |
| 前端 | `views/UsersView.vue` | 编辑弹窗「重置密码」输入框（留空不改，`show-password`）；保存成功后同步调用重置接口并提示「该账号在其它端需用新密码重新登录」 |
| DB（冗余保留） | `worker_db.users.pwd_version` | 迁移 `db/migrations/20260920_v9_pwd_version.sql` 已执行；worker-rpc 改密时 `+1`。A2 下链路不读该列，作为**durable 记录**保留（口径：Redis 缓存 + DB 持久化双记录） |

**失败开放原则**：以下情况一律放行，避免缓存故障锁死全站——未注入缓存、系统身份（定时任务 `uid=0`）、以及**不含 `pwdver` 的旧 token**（等其自然过期）。

## 4. 验收（2026-09-20 实测，全部通过）

| 步骤 | 操作 | 结果 |
| :--- | :--- | :--- |
| A | `water1` 用旧密码登录 → 访问 `/api/worker/orders` | 200 |
| B | 管理员 `POST /api/admin/users/10/reset-password {password:"temp1234"}` | 200 |
| C | **同一旧 token 再访问** | **401**（旧登录态已失效） |
| D | 用新密码登录 → 访问 | 登录成功、200 |
| E | admin 自身 token（未改密） | 200（不受影响） |
| F/G | 密码改回 `admin123` → 重新登录 | 200 / 成功（演示账号已复原） |

## 5. 回滚方式

- 代码：远端标签 `backup/pre-v9.8-20260920-163100`（V9.8 动工前 HEAD）
- 数据：`.tools/backups/rv-backup-20260920-163100.sql`（三库 dump，gitignored）
- 仅回退迁移：`ALTER TABLE users DROP COLUMN pwd_version;`
- 关闭强制失效（临时）：不注入缓存即可（`routes.go` 去掉 `auth.UsePwdVersionStore(...)`），此时校验整体放行

## 6. 注意与运维

- Redis 被清空（非持久化重启）时版本号归 0，已签发 token 会失效 → 用户重新登录即可；compose 已挂 `redis-data` 卷，正常重启不受影响
- 改密后**该账号所有端**（PC 管理端、宿工端、宿管端、微信内页）都需重新登录，包括发起改密的管理员本人以外的会话
- 演示账号统一 `admin123`：演示前若改过密码，记得改回（本轮验收已复原）
