# V8 空间与建筑 3D/2D 可视化重构、工人端地图居中与交互升级（任务与设计总结）

> 版本周期：2026-09-19 ~ 2026-09-20  
> 核心目标：彻底重构 3D/2D 空间建筑可视化模型渲染、优化多端 UI 风格一致性（V4 柔和渐变与玻璃拟态）、工人端地图居中锁定与完工筛选、修复全链路交互缺陷。

---

## 一、需求背景与版本定位

在前期 V7 版本完成公共免登录报修与基础空间展示后，原有的 3D 建筑可视化存在诸多不足：
1. **3D 模型粗糙沉重**：原 3D 模型底色为全黑/深黑背景，且楼层之间存在厚重的灰色隔断层，整体视觉简陋，缺乏现代数字化孪生沙盘的通透与科技感；
2. **故障状态展示单一**：只展示了部分故障报修红点，已修好的房间缺少状态闭环（用户进入 3D 视角后无法区分是“无故障”还是“已修好”）；
3. **交互与操作体验缺陷**：
   - 逐层查看时楼层被强制降到地坪，破坏了楼栋的真实高度感知；
   - 切换楼层重置相机视角，操作不连贯；
   - 房间点击判定错位（如点击 508 弹出 504 详情卡片）；
   - 退出某楼栋后再进入新楼栋时残留上一次楼栋的维修数据。
4. **工人端地图交互痛点**：
   - 工人在双指或滚轮缩放校园地图时，高亮的目标维修楼栋容易移出视野；
   - 工人端缺乏「已完工 / 未完工」楼栋的直观筛选能力。
5. **公共端 UI 不一致**：公共报修端页面与主系统的 V4 柔和渐变、毛玻璃拟态脱节。

因此，**V8 版本作为空间建筑可视化与工人端体验的全面升级版本**，重点攻坚上述核心问题。

---

## 二、核心改造内容与技术实现

### 1. 管理端 & 工人端 3D 可视化沙盘重构
- **材质与场景美化**：
  - 天空与背景全面升级为微水泥蓝灰浅色底（`0xf1f5fb`），地坪采用柔和晶格网格（`GridHelper`），剔除原有多余、厚重的灰色分割层与底座。
  - 房间三态材质定义：
    - **待维修（红色 `#f43f5e`）**：带自发光高亮、顶部悬浮旋转八面体 Beacon 与红色 3D 悬浮房号标牌；
    - **已完工（绿色 `#10b981`）**：带绿色 3D 标牌，标识当前维修周期内已处理完毕；
    - **普通房间（科技蓝 `#93c5fd`）**：半透明微透质感（`opacity: 0.85`）。
- **空间感知与真实高度保持**：
  - 逐层查看时，各楼层保持其在建筑中的绝对高度 `(floor - 1) * floorStep`，不再压平至地面；
  - 切换楼层时保留相机的 Orbit 旋转角度与视距，避免用户视角重置。
- **射线拾取（Raycasting）与点击交互修正**：
  - 重新梳理 Three.js 射线检测与房间 mesh 的 userData 绑定机制，解决网格排序导致的 508 与 504 错位问题；
  - 修复点击弹窗后阻断鼠标悬停的问题，弹窗增加遮罩层点击销毁机制；
  - 彻底修复 `faults is not defined` 的变量作用域报错；
  - 修复多楼栋切换缓存清理逻辑：进入新楼栋前注销上一建筑的几何体与事件监听，重新按新楼栋请求实时工单与空间映射。

### 2. 2D 楼层户型图深度优化
- **视口自适应**：修正 Canvas/SVG 缩放比例计算公式，单层所有房间完整自适应居中呈现，消除原本“只显示局部放大”的问题；
- **状态同步与卡片联动**：
  - 楼层选择器（1F, 2F...）同步标记红点（有待修）与绿点（全完工）；
  - 点击房间弹出维修详情卡片，工人端支持直接「开始维修」与「确认完工」；
  - 建筑卡片在外层展示「X 待修 · Y 已完工」。

### 3. 工人端校园地图与我的楼栋增强
- **校园概览地图缩放锁定居中**：
  - 在 `CampusOverviewMap.vue` 中引入视口中心锚定算法：当工人点击某栋楼并在地图上高亮后，后续的任何缩放（双指缩放手势、鼠标滚轮、缩放 +/- 按钮）均以该高亮楼栋为中心进行视口边距补偿，确保目标楼栋始终牢牢锁定在屏幕中央。
- **楼栋筛选功能（全部 / 未完工 / 已完工）**：
  - 在 `MapView.vue` 顶部引入微胶囊选项卡：`全部(N)`、`未完工(N)`、`已完工(N)`；
  - 楼栋 Chip 区分展示待修红呼吸灯与已完工绿徽标；
  - 切换筛选分类时，自动联动上方校园地图聚焦至第一栋符合条件的楼栋。
- **WebSocket 路由修复**：
  - 将 `MapView.vue` 中错误的 `/ws/worker` 修正为标准的 `/ws/orders`，恢复与后端的实时推送链路。

### 4. 公共端（`/report`）UI 风格统一
- 统一接入 `theme-v4.css` 视觉规范：
  - 顶部增加流光大标题；
  - 增加毛玻璃药丸导航 Tabs（我要报修 / 查询进度）；
  - 输入框、下拉框、单选胶囊均改为磨砂玻璃拟态与微交互悬停动效；
  - 工单卡片规范化状态胶囊（待派工、已派工、维修中、已完工）。

### 5. 后端工单查询扩展
- 修改 `services/order/internal/store/workerboard.go` 中的 `ListActiveOrdersByWorkerWithinDays` 查询逻辑，在工人地图数据（`/api/worker/map-data`）中包含状态 4（已完成）工单，从而为前端已完工房间的 3D 绿色渲染提供数据支撑。

## 四、验证结果

1. **管理端 & 工人端 3D 视觉**：成功呈现浅色清新风格，待修红、已修绿、正常蓝分色清晰，3D 标牌跟随视线转动，点击无错位。
2. **校园地图居中测试**：在移动端无论如何缩放地图，当前楼栋均稳定保持在屏幕正中心。
3. **工人端筛选测试**：切换「未完工 / 已完工」胶囊，楼栋列表与校园地图实时响应并精准过滤。
4. **公共端报修**：微信/移动浏览器访问 `/report` 呈现毛玻璃流光界面，报修与查询交互顺畅。
