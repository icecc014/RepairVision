## 4. V4-S5 布局设计器 v2（自定义区域 + 尺寸编辑）

### 4.1 数据模型升级（layout v2）

保留 v1 兼容，新增"区块层"作为唯一真相：

```json
{
  "version": 2,
  "cols": 6,
  "rows": 10,
  "blocks": [
    { "id": "b1", "type": "room",   "row": 3, "col": 0, "rowSpan": 1, "colSpan": 2, "label": "" },
    { "id": "b2", "type": "corridor","row": 0, "col": 2, "rowSpan": 10, "colSpan": 2 },
    { "id": "b3", "type": "stair",  "row": 0, "col": 0, "rowSpan": 1, "colSpan": 2 },
    { "id": "b4", "type": "custom", "row": 8, "col": 4, "rowSpan": 2, "colSpan": 2, "label": "洗衣房" }
  ]
}
```

- `type`：`room` | `corridor` | `stair` | `public` | `custom`。
- 兼容：读到 v1（只有 `cells`）时，把每个非 `0` 单元格自动转换为 1×1 区块；保存时一律写 v2。
- `cells` 退化为**派生数据**（由 blocks 反推），仅用于兼容旧渲染代码与调试展示，不再存盘。

### 4.2 交互设计

| 操作 | 行为 |
| --- | --- |
| 默认状态 | 不选中任何工具（沿用已修复的交互），网格只读 |
| 点击工具 | 选中笔刷；单击网格放置 1×1 区块 |
| 按住拖动 | 连续放置（仅在按下状态） |
| **双击区块** | 进入该区块的**编辑模式**：区块描边高亮，显示 8 个把手（4 边 + 4 角） |
| 拖动把手 | 按格吸附增减尺寸；左侧/上侧把手拖动时同步移动 `row/col` 并反向调整 span |
| 自定义文字 | 工具栏选「自定义区域」→ 单击放置 → 弹出输入框（≤12 字），确定后写入 `label`；双击已存在区块可改文字 |
| 选中区块 | 右侧显示属性面板：类型、文字、起始行列、跨格数（也可直接输入数字精确设置） |
| 快捷键 | `Ctrl+Z` 撤销 / `Ctrl+Shift+Z` 重做 / `Delete` 删除选中区块 / `Esc` 退出编辑模式 |

### 4.3 算法与边界（重点）

1. **格坐标换算**：把手拖动时把像素位移换算为格数
   `deltaCols = Math.round((mouseX - startMouseX) / cellWidthPx)`，`cellWidthPx = 画布宽度 / cols`
   （画布有缩放时先除以缩放系数），保证"拖一格就加一格、拖回来就减回去"。
2. **碰撞检测**：区块之间不允许重叠（否则 2D/3D 无法一致）。拖动过程中**逐格试探**，遇到冲突即停在最后一个合法位置：
   ```
   for (let step = 1; step <= Math.abs(delta); step++) {
     const candidate = applyDelta(block, sign * step)
     if (!inBounds(candidate) || overlapsAny(candidate, others)) break
     lastValid = candidate
   }
   ```
3. **最小尺寸**：任何方向 span ≥ 1；缩到 1 后继续拖不再变化。
4. **整格约束**：所有几何运算在整数格坐标下进行，渲染时才换算为归一化浮点，避免累计误差。
5. **编号重排**：房间号 = `楼层 × 100 + 序号`，序号按"行优先、其次列"排序后重新编号；只有 `type=room` 参与编号，
   自定义区域/过道/楼梯不占用房间号。编辑过程中实时预览、保存时定稿。
6. **撤销栈**：每次"放置/删除/改尺寸/改文字"操作前把当前 blocks 深拷贝入栈（上限 50），支持连续撤销；
   尺寸拖动只在 `pointerup` 落地一次（拖动过程中不逐帧入栈），避免撤销栈被撑爆。
7. **保存校验**：房间数 ≥ 1；`custom` 区块 `label` 非空；总格数 ≤ 上限（建议 400）；否则给出具体提示。
8. **性能**：网格上限 16×20 = 320 格，碰撞检测为 O(n²)，n ≤ 64，无需空间索引；渲染用 `:key` 稳定 id 避免整表重绘。

### 5.2 排班算法升级（请假感知 + 可配置休息）

`services/worker/internal/logic/generateweeklylogic.go` 改造要点：

1. 入参扩展：`restDaysPerWeek`（默认 1，支持 0~3）、`minPerBuilding`（每楼栋最少在岗，默认 1）、
   `keepManual`（是否保留人工调整过的班次，默认 false=整周重建）。
2. 请假优先固定：先取该周 `status=2` 的请假，得到 `leaveDays[worker]` 集合，这些日子直接排 `OFF`（note="已批准请假"）。
3. 休息配额：`剩余需休息天数 = max(0, restDaysPerWeek - 已请假天数)`；请假已占用的休息不再重复安排，
   避免"休 2 天 + 请假 2 天"导致在岗天数过低。
4. 轮休分配：沿用现有 `assignRestDays` 的错峰策略（同楼栋不同日、优先保楼栋有人），但**候选日集合**改为"该周非请假日的日期"，
   代价函数加入"楼栋在岗人数 < minPerBuilding"的惩罚项（权重高于错峰项）。
5. 班次分配：`assignShiftsForDay` 把请假人视为 OFF；若某楼栋当日 `在岗人数 < minPerBuilding`：
   - 先尝试把该楼栋当日的 `MORNING/AFTERNOON` 合并回 `DAY`（半天班→全天班）以保证有人在岗；
   - 仍不足则记入 `warnings`，返回给前端提示（不阻止生成）。
6. 返回体扩展：`ScheduleListResponse` 增加 `repeated warnings`（如"03-12 1 号宿舍楼 仅 1 人在岗（要求 2 人）"）。
7. 幂等与安全：仍然"清空该周 → 重建"，但重建前把人工修改过的行（`note` 含"人工调整"）单独查出来，`keepManual=true` 时跳过覆盖。

伪代码：

```
leaves      = ListApprovedLeavesBetween(weekStart, weekEnd)      // worker -> set<date>
offDays     = 每名工人固定 OFF 的日期（请假）
restQuota   = max(0, restDaysPerWeek - |offDays[w]|)
restDays    = assignRestDays(workers, buildings, weekSeed, offDays, restQuota, minPerBuilding)
for day in 0..6:
    shifts = assignShiftsForDay(workers, buildings, offDays ∪ restDays[day], minPerBuilding)
    warnings += coverageCheck(buildings, shifts, minPerBuilding)
```

### 数据模型 v2（区块 + 跨格 + 文字）

```json
{ "version": 2, "cols": 6, "rows": 10,
  "blocks": [ { "id": "b1", "kind": "room", "row": 3, "col": 0, "rowSpan": 1, "colSpan": 2, "label": "洗衣房" } ] }
```

- `kind`：`room` / `corridor` / `stair` / `public` / `custom`。
- **v1 自动升级**：读到只有 `cells` 的旧布局时，每个非 0 格自动转为 1×1 区块，保存时写回 v2；老楼栋无需手工迁移。
- `parseLayout` 会丢弃越界或与他人重叠的区块，保证"任何来源的 JSON 都不会产生重叠布局"；`serializeLayout` 一律输出 v2。
- 房间号仍为 `楼层 × 100 + 顺序`，顺序 = 行优先、其次列，**只有 room 参与编号**；自定义区域不编号、不接收工单红点。

### 算法（已抽为纯函数并单测）

`frontend/*/src/utils/layoutGrid.ts` 新增并在两端共用：

- `stepResize(grid, base, handle, dx, dy)`：把像素位移换算出的格数逐步试探，**每一步**都检查 `colSpan/rowSpan ≥ 1`、是否越界、是否与他人重叠，遇到冲突停在最后一个合法位置。
